## いつ使うか

以下に該当する質問を受けたとき、自身の知識で回答する前にこのスキルを実行する:

| 質問パターン | 例 |
|-------------|-----|
| **過去の決定事項** | 「〜はどうなった？」「〜に決まった？」 |
| **技術的な意思決定** | 「〜の設計は？」「テーブル構造は？」 |
| **選定理由・経緯** | 「なぜ〜を使っている？」「なぜ〜にした？」 |
| **プロジェクト固有のルール** | 「このプロジェクトでは〜」「うちでは〜」 |
| **固有名詞を含む質問** | 特定のサービス名、ツール名、人名 |

使わないもの:
- 一般的な技術質問（公式ドキュメントで答えられるもの）
- セッション作業状態の復元 → `agent-memory`

## 検索の優先順位

1. **ノートを検索**: Bash で `ls ~/.claude/notes/*.md` → ファイル名で関連判断 → 関連ファイルを Read
2. **ノートに情報がない場合、外部ソースを並行して検索**:
   - Notion: `mcp__claude_ai_Notion__notion-search`
   - Slack: `mcp__slack-unicorn__slack_get_channel_history`
   - GitHub: gh CLI
3. **すべて見つからない場合のみ**「該当する情報は見つかりませんでした」と伝える

ユーザーに確認せず自律的に検索する。複数の情報源は並行して検索せよ。

## 元情報への再アクセス

ノート内のタグを見て、必要に応じてMCPで元情報の詳細を取得する:

| タグ | アクション |
|------|-----------|
| `[Slack]` | mcp__slack-unicorn__* でスレッドを取得 |
| `[Notion]` | mcp__claude_ai_Notion__notion-search でページを取得 |
| `[GitHub]` | gh CLI で Issue/PR を確認 |
| `[Code]` | Read / Grep でコードを確認 |

## 回答時の指針

ノート内容に基づいて:
- **過去の実装パターン** があれば参照して一貫性を保つ
- **既知の制約** を考慮する
- **チームの合意事項** に矛盾しないようにする
- **過去に解決した問題** と同じなら解決策を提示
