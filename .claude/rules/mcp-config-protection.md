# MCP設定の保護ルール

## 設定ファイルの変更禁止
- `.mcp.json` / `mcp.json` の変更はPreToolUseフックでブロックされる
- 変更が必要な場合はユーザーに手動編集を依頼すること

## sh -c ラッパーの簡略化禁止
- MCP serverの `sh -c` ラッパーを `uvx` / `npx` / `bunx` 等の直接実行形式に変更してはならない
- `sh -c` ラッパーはenv var sourcing やPATH設定のために意図的に使用されている

## MCP接続障害のデバッグ手順
1. **必ず最初に** `mcp-doctor` を実行し、バイナリ・env ファイル・証明書の存在を一括確認
2. env var sourcing（`.env`、シェルプロファイル）を確認
3. 相対パス・絶対パスの整合性を確認
4. バイナリの存在確認（`which uvx` 等）
5. コマンド構造の変更は最後の手段とし、ユーザー承認を得ること

## mcp-doctor の実行タイミング
- MCP接続障害が発生したとき（**最優先で実行**）
- 新しい端末・環境で初回セットアップ後
- `.mcp.json` を手動変更した後
