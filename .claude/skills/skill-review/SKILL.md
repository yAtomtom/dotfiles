# Skill Review

スキルの作成・修正・レビュー時に、プロジェクト固有の設計指針を適用する。

## いつ使うか

| 場面 | 例 |
|------|-----|
| **スキルの新規作成** | 「〜のスキルを作りたい」 |
| **既存スキルの修正** | 「〜スキルを改善して」 |
| **スキル設計のレビュー** | 「スキルの設計をレビューして」 |
| **SKILL.mdの記述** | 「SKILL.mdを書いて」 |

## 手順

1. `~/.claude/notes/skill-設計.md` を Read して設計指針をロードする
2. `~/.claude/notes/skill-frontmatter.md` を Read してfrontmatterの注意点をロードする
3. 上記の指針に基づいてスキルの作成・修正・レビューを行う

## レビュー観点（skill-設計.md の要約）

以下の観点でスキルを評価する。詳細は notes を参照:

- **SKILL.md の役割**: 手続きの列挙ではなく、判断基準を前面に出したオーケストレーターになっているか
- **description のトリガー精度**: 具体的なトリガー条件・質問パターンが明示されているか
- **セキュリティルールとの整合**: 信頼境界の優先順位を逸脱していないか
- **スキル間の境界**: 目的が1対1で重複なく定義されているか、「使わないもの」が明示されているか
- **Orchestration パターン**: 並列検索など、パフォーマンスに影響する指示が明示的か
- **コンテキスト効率**: SKILL.md が500行以下か、大きなリソースは外部ファイルに切り出されているか
- **frontmatter**: サポートされている属性のみ使用し、description は1行のダブルクォートで記述されているか
