# Memex Recall

保存されたノートから過去の情報を参照します。

## 処理手順

1. **ファイル一覧取得**: Bash で `ls ~/.claude/notes/*.md` を実行（Globは`~`を展開できないため）
2. **関連トピック判断**: ファイル名（トピック名）を見て、質問に関連しそうか判断
3. **関連ファイルを Read**: 関連しそうなファイルだけ読む（全部読む必要なし）
4. **回答**: ノート内容に基づいて回答
5. **ノートに情報がない場合**: 質問の内容から最も情報がありそうな場所を自律的に判断して検索
   - **Notion**: 仕様書、設計ドキュメント、ナレッジベース、議事録 → `mcp__claude_ai_Notion__notion-search`
   - **Slack**: 最近の議論、進捗、障害対応、チーム間のやり取り → `mcp__slack-unicorn__slack_get_channel_history`
   - **GitHub**: Issue、PR、コードに関する議論 → gh CLI
   - 複数の情報源を並行して検索してもよい
   - 情報が見つかったら回答し、見つからなければその旨を伝える

## 参照時の指示

ノート内容に基づいて：

1. **過去の実装パターン** - 同様の実装があれば参照して一貫性を保つ
2. **既知の制約** - 記録された制約や仕様を考慮する
3. **チームの合意事項** - 決定事項に矛盾しないようにする
4. **トラブルシューティング** - 過去に解決した問題と同じなら解決策を提示

## 出力フォーマット

回答の最後に必ず**情報源**を添える：

```
[回答内容]

**情報源:**
- Slack: #channel-name [リンク]
- Notion: ページ名 [リンク]
- GitHub: org/repo#123 [リンク]
- Web: [URL]
```

ノートに記載されているURL、チャンネル名、PR番号などをそのまま出力する。

## 元情報へのアクセス

ノート内のタグを見て、必要に応じてMCPで元情報にアクセスする：

| タグ | アクション |
|------|-----------|
| `[Slack]` | mcp__slack-unicorn__* でチャンネル/スレッドを検索 |
| `[Notion]` | mcp__claude_ai_Notion__notion-search / mcp__notion__* でページを取得 |
| `[GitHub]` | gh CLI で Issue/PR を確認 |
| `[Code]` | Read / Grep でコードを確認 |

ノートに情報がない場合は、ユーザーに確認せずに自動的に Notion → Slack の順で検索を行うこと。すべての情報源を調べても見つからなかった場合のみ「該当する情報は見つかりませんでした」と伝える。
