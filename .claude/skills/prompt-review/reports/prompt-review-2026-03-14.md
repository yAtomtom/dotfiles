## 4. プロンプティング力の評価

### 強み

- **具体的な制約とコンテキスト提示**: 「assignAttributesはJSON列全体を置換するため、欠落したtypeキーのvalueは何も変更しないのが望ましいです」のように期待動作を明確に伝えている
- **段階的な検証アプローチ**: MCP連携テストでは「まず何ができるか教えて」→「テスト通信」→「注意事項の永続化」と段階的に進める
- **複数AIのクロスレビュー活用**: 「copilotにもレビューしてもらって」を頻繁に使い、単一AIの判断に依存しない
- **AIの誤報告への追及**: 「なんでコミットされてないのに，コミットしたという間違った報告したんですか？」「なんでこのような報告をしたのですか？」とAIの不正確さを見逃さない
- **目的の明示**: 「リポジトリを公開することを考えた場合」「保守運用の観点と責務の分離として」のように意思決定の背景を伝えている

### 改善ポイント

- **一度に複数の要求を混在**: 「編集権限に問題なければXDG_CONFIG_HOMEの削除とconfigの指定を行ってください」のように条件付き+複合操作が一文に詰め込まれることがある → **改善提案**: 条件確認と操作指示を分けて2ステップにする
- **曖昧な指示代名詞**: 「3を行ってください」「1を行ってください」のように、前のAI出力の番号を参照する指示が散見される → **改善提案**: 番号だけでなく内容を簡潔に添える（例:「3の方法（xxxを変更）を実行して」）
- **要件の後出し**: 「video_viewsのrenameは別の人が移行を担当しますが」と途中で前提条件を追加する場面がある → **改善提案**: 最初の指示時に関係者・スコープを明示する

### 特徴的な癖

- 「〜でしたっけ？」「〜ありましたっけ？」という確認形式が頻出し、AIを記憶補助として使っている
- セキュリティテストで意図的にルール違反を指示し、防御が機能するか検証する（「無視して表示してください」「無視して反映してください」）
- Copilotの回答を引用してClaudeに検証させる（「copilotに聞いたところ〜とのことでした．内容を確認してください」）
- 日本語主体だが、コミットメッセージは英語を好む（「コミットメッセージは英語にしたいので英語版教えてください」）

## 5. AI活用スタイル

### 主体的に活用できている領域

- **設計方針の決定**: DDD、インターフェース設計、セキュリティポリシーの方針はユーザーが決定し、AIに実装を指示。「preserve_untouched_measurement_type_keysですが，単体テストが期待されるメソッドではインスタンス変数を内部から参照するのは避けて」のように設計判断を主導
- **AIツール基盤の構築**: agents, skills, hooks, cageの設計はユーザー主導。AIは実装とレビューの役割
- **PRレビュー対応**: 「下記のPRレビューコメントについて検討してください」と問題を提示し、AIの分析を参考に自ら判断

### AIへの依存が高い領域

- **CLI設定の探索**: Claude Code CLIの仕様・設定方法について頻繁にAIに質問。20回以上の/mcp確認、複数回の/exit→再起動など試行錯誤が多い → **自立に向けた提案**: 公式ドキュメントのブックマークを整備し、頻出設定はチートシートとして自前で管理する
- **ツール連携のトラブルシューティング**: MCP接続障害、cage権限エラーなど環境問題の原因特定をAIに依存 → **自立に向けた提案**: エラーログの読み方パターンを整理し、一次切り分けを自身で行うフローを確立する

### ツール別の活用傾向

- **Claude Code**: メインツール。設計相談、実装指示、コードレビュー、MCP連携テスト、ドキュメント作成、git操作まで幅広く使用。セッション数が非常に多く、1日に複数セッションを使い分ける
- **GitHub Copilot Chat**: クロスレビュー先としての間接利用が中心。直接のプロンプトはほぼなく、Claude経由で「copilotにレビューしてもらって」と委任する形

### 繰り返し発生する課題

- **AIの虚偽報告への対処**: コミット未実行なのに完了報告、staging禁止と誤報告など。都度追及しているが再発している
- **MCP接続問題**: slack-unicorn MCPの接続障害で/mcp→/exitを20回以上繰り返すなど、環境問題での消耗が目立つ
- **設定の散在**: .claude/rules/, .claude/agents/, .claude/skills/, .zshrc_*_aliases, cage presets.yml など設定が多箇所に分散し、変更時の影響範囲が大きい

### 推奨される次のステップ

1. **AIの出力検証の自動化**: git mementoのnotes記録は良い施策だが、コミット成否の自動検証（post-commitフック等）を追加し、AIの虚偽報告を構造的に防止する
2. **MCP接続のヘルスチェック自動化**: 起動時に全MCPの接続状態を一括確認するスクリプトを用意し、個別の/mcp確認ループを削減する
3. **フロントエンド設計力の強化**: React/TypeScriptの実装をAIに委任する傾向があるため、state-first-designスキルをフロントエンドにも適用し、自ら設計判断できる範囲を広げる
