---
description: "PRのレビューコメントを精査し、妥当な指摘に対して修正・コミットまで実施する"
---

レビュー結果を確認し、妥当性を判断した上で必要な修正とコミットを行います。
レビュアーの指摘がすべて正しいとは限らないため、各コメントを批判的に評価します。

## 使用方法

```
/address [PR番号 | URL | ファイルパス]
```

### 引数の解釈

- **無引数**: 直前の会話に含まれるレビュー内容を対象とする
- **数値のみ**: PR番号として解釈し、`gh api` でコメントを取得
- **github.com を含むURL**: GitHub PR URLとして解釈し、PR番号を抽出して `gh api` でコメントを取得
- **上記以外**: ファイルパスとして解釈し、レビュー内容が記載されたファイルを読み込む

### 引数: $ARGUMENTS

## 動作フロー

### 1. レビューコメント取得

引数を解釈し、レビューコメントを取得・読み込む。
PR番号が特定できた場合、以下の2つのAPIで全コメントを取得する:
- `gh api repos/{owner}/{repo}/pulls/{番号}/reviews` — レビュー本文
- `gh api repos/{owner}/{repo}/pulls/{番号}/comments` — コードへのインラインコメント

### 2. 各コメントの妥当性を評価（セルフレビュー）

各コメントについて以下の観点で妥当性を判断し、判定表を出力する:
- 技術的に正しいか
- プロジェクトの方針・コンテキストと合致するか
- 実装上のトレードオフとして妥当か

#### 判定表の形式

```markdown
| # | 指摘 | 判定 | 対応 | 理由 |
|---|------|------|------|------|
| 1 | 指摘の要約 | 妥当 / 不要 | 修正する / 対応不要 | 判断理由 |
```

### 3. クロスレビュー

判定表を `~/claude-sandbox/` にファイルとして出力し、Copilotにクロスレビューを実行する。

```bash
command copilot --model "gpt-5.2-codex" --add-dir $HOME/claude-sandbox/ -p "~/claude-sandbox/<判定表ファイル名> をレビューしてください"
```

- **判定が一致**: 確認不要でそのまま進行
- **判定が分かれた場合**: ユーザーに提示し確認を取る
- **スキップ条件**: 修正対象が0件の場合はクロスレビューをスキップし、判定表と最終サマリーのみ出力して終了する

### 4. 妥当な指摘のみ修正を実施

クロスレビューで確定した修正対象の指摘についてのみ、コード修正を実施する。

### 5. コミット

修正がある場合のみ実施する:
1. `git diff` で差分をユーザーに提示する
2. ユーザーの承認を得る
3. `git add`（修正対象ファイルのみ）
4. `git commit`

### 6. 最終サマリーを出力

## 最終サマリーの形式

```markdown
## レビュー対応サマリー

### 対応した指摘
| 指摘 | 修正内容 |
|------|----------|
| 指摘1 | 修正の概要説明 |

### 対応しなかった指摘
| 指摘 | 理由 |
|------|------|
| 指摘X | 対応不要と判断した理由 |
```

## 注意事項

- レビュアーの指摘を鵜呑みにせず、技術的妥当性を独自に判断する
- 対応しない場合は、レビュアーが納得できる理由を明記する
- 修正によって新たな問題が発生しないか確認する
- 返信の投稿は `/reply-review` で別途実行する（このコマンドの責務はコード修正・コミットまで）
